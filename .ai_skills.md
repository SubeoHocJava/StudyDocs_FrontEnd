# Flutter Clean Architecture - Screen Structure

Skill này hướng dẫn AI cấu trúc các màn hình (screens) theo chuẩn Clean Architecture trong thư mục `lib/screens/` của dự án.

## Quy tắc thiết kế (Design Rules)

Khi tạo một màn hình mới (ví dụ `feature_name`), luôn tuân thủ cấu trúc thư mục sau:

```text
lib/screens/{feature_name}/
├── data/                  # Chứa các class implementation của repository và data sources.
│   └── repository/        # Ví dụ: feature_repository_impl.dart
├── domain/                # Chứa logic kinh doanh cốt lõi (không phụ thuộc Flutter/UI).
│   ├── entity/            # Các model data cốt lõi (ví dụ: feature_model.dart)
│   ├── repository/        # Các interface (abstract class) của repository.
│   └── usecase/           # Các UseCase để tầng logic gọi.
├── logic/                 # Chứa State Management (Thường là BLoC hoặc Cubit).
│   ├── feature_bloc.dart
│   ├── feature_event.dart
│   └── feature_state.dart
└── presentation/          # Chứa giao diện hiển thị chính.
    ├── feature_screen.dart # Tên file và class phải đúng với tên màn hình (VD: FeatureScreen).
    ├── widgets/           # CÁC COMPONENT, WIDGET NHỎ CỦA MÀN HÌNH NÀY SẼ NẰM Ở ĐÂY HOẶC TRONG CORE/WIDGETS.
    └── utils/             # Các hàm hoặc mapper chỉ dùng cho UI màn hình này.
```

## Lưu ý quan trọng (Important Notes)

1. **Phân tách Widgets (Components):** 
   - Những widget/component chỉ dùng cho 1 screen cụ thể thì NÊN đặt ở `screens/{feature_name}/presentation/widgets/`.
   - Nếu widget/component là loại có thể dùng chung (reusable) hoặc theo chỉ định của developer, chúng có thể được giữ tại `core/widgets/feat/{feature_name}/presentation/widgets/`. Trong trường hợp này, tuyệt đối không được đặt `domain`, `logic`, hay `data` vào trong `core/widgets`, mà phải di chuyển chúng về thư mục `screens/` như cấu trúc trên.
   
2. **Quy tắc Import:** 
   - Các file trong `domain` không được import bất kỳ thứ gì từ `data`, `logic`, hay `presentation`.
   - Các file trong `logic` chỉ được gọi tới `domain/usecase`.
   - Các component trong `core/widgets` có thể import Entity từ `domain` của Screen, nhưng nên hạn chế phụ thuộc vào Bloc cụ thể nếu có thể (để có thể tái sử dụng dễ hơn).

3. **Đặt tên file và class:** 
   - Tên file sử dụng chuẩn `lower_case_with_underscores.dart`.
   - Tên class sử dụng chuẩn `UpperCamelCase`.
   - Màn hình chính luôn kết thúc bằng chữ `Screen` (Ví dụ: `NotificationScreen`).

## Quy trình tạo tính năng mới (New Feature Creation Process)

Khi người dùng yêu cầu "tạo tính năng X tương tự như các widget khác", hãy thực hiện tuần tự:

1. **Khởi tạo Domain:** Tạo Entity (Model), Repository Interface, và UseCase(s) ở `screens/{feature}/domain/`.
2. **Khởi tạo Data:** Tạo Repository Implementation (có thể là mock ban đầu) ở `screens/{feature}/data/repository/`.
3. **Khởi tạo Logic (Bloc):** Tạo Event, State, và Bloc ở `screens/{feature}/logic/`. Sử dụng UseCase trong Bloc.
4. **Xây dựng UI Components:** Tạo các UI Widgets nhỏ lẻ tĩnh ở `core/widgets/feat/{feature}/presentation/widgets/`.
5. **Ráp nối vào Screen:** Tại `screens/{feature}/presentation/{feature}_screen.dart`, bọc UI bằng `BlocProvider` (cung cấp Mock Repository và các UseCase) và ráp nối với Bloc/UI components.
